## 目标与前置
准备和体验回归通过后，把“原文与旁注”迁入主应用，保留现有记录。

## 验收标准
- [ ] 先提交明确的数据映射、版本兼容、备份/恢复方案；不直接覆盖两个存储键。
- [ ] 只用虚构旧版 fixtures 验证记录、日期、草稿和未知感受不会丢失或变默认分数。
- [ ] 写入失败可恢复，重复迁移不重复记录，不清空源数据。
- [ ] 新主应用保留原文、换行、单条保存、日期轴和手机旁注排版。
- [ ] 明确选择唯一正式入口，旧体验稿标明用途；不混淆模型与示例。
- [ ] npm test 与真实浏览器回归通过，输出兼容性证据。

## Agent 边界
由主 Agent 先决定契约与文件归属；app.js 同一轮只有一个写入者。
不读取真实用户存储，不擅自迁移私人日记，不为并行工作无目的地大拆模块。
